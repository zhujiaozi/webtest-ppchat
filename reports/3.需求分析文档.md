# PP 在线聊天系统 — 需求分析文档

## 一、项目概述

### 1.1 项目名称
PP 在线聊天系统（PP Chat）

### 1.2 项目背景
本项目为《Web程序设计（Java EE）》课程大作业，选题为"题目3：在线聊天系统（85分）"。目标是实现一个功能完整的 Web 即时通讯系统，支持用户注册登录、好友管理（分组）、一对一私聊、多人群聊、语音消息、聊天记录查询与导出等核心功能。

### 1.3 评分目标对照

| 课程要求 | 对应功能模块 | 实现状态 |
|----------|-------------|---------|
| 登录与注册 | 用户认证模块 | ✅ 已实现 |
| 聊天管理（私聊、群聊） | 私聊模块 + 群聊模块 | ✅ 已实现 |
| 查询聊天记录，下载到本地 | 聊天记录搜索 + TXT 导出 | ✅ 已实现 |
| 语音聊天（+5分） | 语音消息模块 | ✅ 已实现 |
| 好友管理（分组、移动、删除、重新发送验证信息） | 好友管理模块 + 通知中心 | ✅ 已实现 |
| （附加）后台管理系统 | Admin 管理后台 | ✅ 已实现 |

## 二、功能性需求

### 2.1 用户认证模块

#### 2.1.1 用户注册
- **描述**：新用户通过填写用户名、密码、昵称（可选）完成注册。
- **输入**：用户名（必填，唯一）、密码（必填）、昵称（可选）
- **处理**：
  - 检查用户名是否已存在
  - 使用 BCrypt 对密码进行加密存储
  - 创建用户记录，初始化登录次数为 0
- **输出**：注册成功跳转至登录页；失败则显示错误信息

#### 2.1.2 用户登录
- **描述**：已注册用户通过用户名和密码登录系统。
- **输入**：用户名、密码
- **处理**：
  - 根据用户名查询用户
  - 使用 BCrypt 验证密码
  - 登录成功后将用户对象存入 HttpSession
  - 更新最近登录时间和登录次数
- **输出**：登录成功跳转至聊天主界面；失败则显示"用户名或密码错误"

#### 2.1.3 用户登出
- **描述**：用户主动退出登录。
- **处理**：
  - 将用户状态设为离线（status=0）
  - 销毁 HttpSession
- **输出**：重定向至登录页

#### 2.1.4 忘记密码
- **描述**：用户忘记登录密码时，可通过用户名直接重置密码。
- **输入**：用户名、新密码
- **处理**：
  - 根据用户名查找用户
  - 若用户存在，使用 BCrypt 加密新密码并更新
- **输出**：密码重置成功提示

#### 2.1.5 个人中心
- **描述**：登录用户查看和修改个人信息。
- **功能**：
  - 查看个人资料（头像、昵称、用户名、用户ID、登录次数、最近登录时间）
  - 修改昵称
  - 上传头像（MultipartFile 文件上传）
  - 修改密码（需验证原密码）

### 2.2 好友管理模块

#### 2.2.1 搜索用户
- **描述**：用户可以通过关键词搜索其他用户以添加好友。
- **输入**：搜索关键词（用户名或昵称模糊匹配）
- **处理**：在数据库中执行 LIKE 查询，排除当前用户自身
- **输出**：返回匹配的用户列表，每个用户显示昵称/用户名和"加好友"按钮

#### 2.2.2 发送好友申请
- **描述**：用户向其他用户发送好友申请，可附带验证消息。
- **输入**：目标用户ID、验证消息（可选）
- **处理**：
  - 检查是否已是好友
  - 检查是否已有待处理的申请
  - 创建好友申请记录（status=0 待处理）
- **输出**：申请发送成功提示

#### 2.2.3 处理好友申请
- **描述**：用户可以查看收到的好友申请，选择同意或拒绝。
- **输入**：申请ID、操作（同意/拒绝）
- **处理**：
  - 同意：将申请状态设为 1，在 friend 表中插入双向好友记录
  - 拒绝：将申请状态设为 2
- **输出**：操作成功提示，刷新好友申请列表

#### 2.2.4 好友分组管理
- **描述**：用户可以创建、重命名、删除好友分组。
- **功能**：
  - 创建分组：输入分组名称，创建新的 FriendGroup 记录
  - 重命名分组：修改现有分组的名称
  - 删除分组：删除分组前先将该组内所有好友移至未分组（groupId=null）
- **默认分组**：用户首次添加好友时自动创建"我的好友"默认分组

#### 2.2.5 移动好友
- **描述**：用户可以将好友从一个分组移动到另一个分组。
- **输入**：好友ID、目标分组ID
- **处理**：更新 friend 表中的 groupId 字段
- **输出**：移动成功提示

#### 2.2.6 设置备注
- **描述**：用户可以为好友设置备注名，方便识别。
- **输入**：好友ID、备注名
- **处理**：更新 friend 表中的 remark 字段
- **输出**：备注设置成功提示

#### 2.2.7 删除好友
- **描述**：用户可以删除好友关系。
- **输入**：好友ID
- **处理**：从 friend 表中删除双向的好友记录（A→B 和 B→A）
- **输出**：删除成功提示

### 2.3 私聊模块

#### 2.3.1 发起私聊
- **描述**：用户从好友列表中点击好友头像进入私聊界面。
- **处理**：
  - 加载与该好友的历史聊天记录
  - 建立 WebSocket 连接并订阅 `/user/{userId}/queue/private`
- **输出**：显示聊天界面，包含历史消息和输入框

#### 2.3.2 发送文本消息
- **描述**：用户在私聊中输入文本并发送。
- **输入**：消息内容
- **处理**：
  - 前端乐观更新，立即显示消息（带发送中状态）
  - 通过 STOMP 发送至 `/app/chat/private`
  - 后端保存至 private_message 表
  - 推送至接收方的 `/user/{receiverId}/queue/private`
- **输出**：消息出现在双方聊天窗口中

#### 2.3.3 发送语音消息
- **描述**：用户按住录音按钮录制语音并发送。
- **输入**：音频数据（最长 10 秒）
- **处理**：
  - 浏览器使用 MediaRecorder API 录制音频
  - 将音频 Blob 转为 Base64 编码
  - 通过 STOMP 发送（msgType=1, audioData=base64String）
  - 后端保存至 private_message 表
- **输出**：语音消息气泡出现在聊天窗口，点击可播放

#### 2.3.4 消息状态
- **描述**：每条消息有三种状态：已发送(0)、已送达(1)、已读(2)。
- **处理**：
  - 发送时 status=0
  - 接收方收到 WebSocket 推送时 status=1
  - 接收方打开会话时调用 REST API 批量标记为已读 status=2

#### 2.3.5 未读消息计数
- **描述**：会话列表显示每个好友的未读消息数量。
- **处理**：查询 private_message 表中 receiverId=当前用户 AND senderId=好友 AND status<2 的记录数
- **输出**：在会话项右上角显示红色数字徽章

#### 2.3.6 聊天记录搜索
- **描述**：用户可以在私聊中搜索历史消息。
- **输入**：搜索关键词
- **处理**：在 private_message 表中执行 LIKE 查询
- **输出**：高亮显示匹配的消息

#### 2.3.7 聊天记录导出
- **描述**：用户可以将私聊记录导出为 TXT 文件下载。
- **处理**：
  - 查询完整对话记录
  - 批量加载发送者信息（避免 N+1 查询）
  - 格式化为 `[时间] 发送者: 内容` 的文本
  - 语音消息显示为 `[语音消息]`
- **输出**：浏览器下载 chat.txt 文件

### 2.4 群聊模块

#### 2.4.1 创建群聊
- **描述**：用户可以创建群聊并邀请好友加入。
- **输入**：群名称、成员ID列表
- **处理**：
  - 创建 GroupChat 记录
  - 创建者为群主（role=2）
  - 被邀请者为普通成员（role=0）
- **输出**：群聊创建成功，跳转至群聊界面

#### 2.4.2 群消息收发
- **描述**：群成员可以发送和接收群消息。
- **处理**：
  - 发送：STOMP → `/app/chat/group` → 保存至 group_message 表 → 广播至 `/topic/group/{groupId}`
  - 接收：订阅 `/topic/group/{groupId}` 的成员实时收到消息

#### 2.4.3 群成员管理
- **描述**：群主可以踢出成员，成员可以主动退群。
- **功能**：
  - 踢出成员：群主调用 `DELETE /api/groups/{id}/members/{userId}`
  - 退出群聊：成员调用 `POST /api/groups/{id}/leave`
  - 解散群聊：群主调用 `DELETE /api/groups/{id}`，删除所有成员记录和群记录

#### 2.4.4 群公告
- **描述**：群主可以编辑群公告。
- **输入**：公告内容
- **处理**：更新 GroupChat 表中的 notice 字段
- **输出**：公告更新成功提示

#### 2.4.5 群聊邀请与入群申请
- **描述**：群聊支持两种加入方式。
- **邀请**：群主邀请非成员用户加入群聊。
  - 创建 GroupInvitation 记录（type=0 邀请，status=0 待处理）
  - 被邀请者在"通知中心"看到邀请
  - 同意：status=1，添加为群成员
  - 拒绝：status=2
- **入群申请**：非成员用户主动申请加入群聊。
  - 创建 GroupInvitation 记录（type=1 申请，status=0 待处理）
  - 群主在"通知中心"看到入群申请
  - 同意：status=1，添加申请者为群成员
  - 拒绝：status=2

#### 2.4.6 群聊天记录导出
- **描述**：群成员可以导出群聊天记录。
- **处理**：同私聊导出，格式为 `[时间] 发送者: 内容`
- **输出**：浏览器下载 group-chat.txt 文件

### 2.5 通知中心模块

#### 2.5.1 通知合并展示
- **描述**：将好友申请、群聊邀请、入群申请三种通知统一展示在"通知"视图。
- **左栏**：显示所有通知列表，按类型区分标签（好友申请/群聊邀请/入群申请）
- **右栏**：点击通知查看详情，显示同意/拒绝按钮
- **搜索**：按通知对象名称前端筛选

#### 2.5.2 添加好友入口
- **描述**：在好友列表左栏顶部提供"添加好友"按钮。
- **处理**：点击后右栏显示搜索面板，搜索用户并发送好友申请

### 2.6 后台管理模块

#### 2.6.1 管理员登录
- **描述**：管理员通过独立的登录页面（`/admin/login`）登录后台。
- **处理**：独立的 Session 管理，与用户 Session 隔离
- **默认账号**：系统首次启动自动创建默认管理员（admin/admin123）

#### 2.6.2 仪表盘
- **描述**：展示系统整体数据统计。
- **输出**：用户总数、好友关系数、私聊消息数、群聊数量、群消息数等 9 项统计

#### 2.6.3 数据管理
- **描述**：管理员可查看和管理全部 9 张数据表。
- **功能**：
  - 用户管理：查看、搜索、重置密码、删除用户（级联删除所有关联数据）
  - 好友关系：查看、删除
  - 好友分组：查看、删除
  - 好友请求：查看、删除
  - 私聊消息：查看、删除
  - 群聊管理：查看、删除
  - 群成员：查看、删除
  - 群消息：查看、删除
  - 群邀请：查看、删除（区分邀请与申请类型）
- **搜索**：每个管理页面都有搜索栏，支持按关键词筛选

#### 2.6.4 用户级联删除
- **描述**：管理员删除用户时，自动清理该用户的所有关联数据。
- **处理**：依次删除用户创建的群聊（含群消息、群成员、群邀请）→ 其他群的成员记录 → 用户发送的群消息 → 群聊邀请 → 私聊消息 → 好友关系 → 好友分组 → 好友请求 → 用户本身

### 2.7 个人中心模块

#### 2.5.1 查看个人资料
- **描述**：用户查看自己的基本信息。
- **输出**：显示头像、昵称、用户名、登录次数、最近登录时间

#### 2.5.2 修改昵称
- **描述**：用户可以修改自己的昵称。
- **输入**：新昵称
- **处理**：更新 User 表中的 nickname 字段
- **输出**：昵称更新成功提示

#### 2.5.3 修改密码
- **描述**：用户可以修改登录密码。
- **输入**：原密码、新密码
- **处理**：
  - 验证原密码是否正确
  - 使用 BCrypt 加密新密码并更新
- **输出**：密码修改成功提示

## 三、非功能性需求

### 3.1 性能要求
- 页面加载时间 < 2 秒
- WebSocket 消息延迟 < 500ms
- 支持至少 50 人同时在线聊天

### 3.2 安全性要求
- 密码使用 BCrypt 加密存储
- Session 超时自动登出
- WebSocket 连接需通过 Session 认证
- 防止 XSS 攻击（前端转义用户输入）
- 防止 SQL 注入（使用 JPA 参数化查询）

### 3.3 可用性要求
- 界面简洁直观，符合微信/QQ 风格
- 支持亮色/暗色主题切换
- 响应式设计，适配不同屏幕尺寸
- 操作反馈及时（Toast 提示）

### 3.4 兼容性要求
- 支持 Chrome、Firefox、Edge 等现代浏览器
- 支持 Windows、macOS、Linux 操作系统

## 四、数据需求

### 4.1 核心实体
- User（用户）
- Admin（管理员）
- FriendGroup（好友分组）
- Friend（好友关系）
- FriendRequest（好友申请）
- PrivateMessage（私聊消息）
- GroupChat（群聊）
- GroupMember（群成员）
- GroupMessage（群聊消息）
- GroupInvitation（群聊邀请/入群申请，type字段区分）

### 4.2 数据存储
- MySQL 8.0 关系型数据库
- 文件存储：头像、语音文件存储在服务器文件系统
