# PP 在线聊天系统 — 系统设计文档

## 一、系统架构设计

### 1.1 整体架构

PP Chat 采用**混合架构**：管理类页面（登录注册、好友管理、群管理、个人资料）使用 Thymeleaf 服务端渲染；聊天核心页面使用原生 JavaScript + WebSocket STOMP 实时通信。单体 Spring Boot 部署，无跨域问题。

### 1.2 技术栈选型

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| Web框架 | Spring Boot 4.0.6 | 快速开发、自动配置、内嵌Tomcat |
| 持久层 | Spring Data JPA + Hibernate | ORM映射、简化CRUD操作 |
| 数据库 | MySQL 8.0 | 关系型数据库、支持事务 |
| 模板引擎 | Thymeleaf | 服务端HTML渲染、自然模板 |
| 实时通信 | WebSocket STOMP | 双向实时通信、发布订阅模式 |
| 前端客户端 | SockJS + StompJS | WebSocket降级支持、STOMP协议 |
| 密码加密 | BCrypt (Spring Security) | 单向哈希、防彩虹表攻击 |
| 代码简化 | Lombok | 自动生成getter/setter/构造器 |
| 音频处理 | MediaRecorder API | 浏览器原生录音、WebM格式 |

## 二、模块详细设计

### 2.1 用户认证模块

#### 2.1.1 类设计

**UserService.java**
```java
@Service
public class UserService {
    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    // 注册：检查用户名唯一性，BCrypt加密密码
    public String register(String username, String password, String nickname);

    // 登录：验证密码，更新登录信息
    public User login(String username, String password);

    // 根据ID查询用户
    public User getById(Long id);

    // 批量查询用户
    public List<User> getByIds(List<Long> ids);

    // 更新用户资料
    public void updateProfile(User user);

    // 修改密码
    public void updatePassword(User user, String newPassword);

    // 重置密码（忘记密码）
    public String resetPassword(String username, String newPassword);
}
```

#### 2.1.2 安全设计
- **密码存储**：使用 BCryptPasswordEncoder，每次加密结果不同（加盐），防止彩虹表攻击
- **Session管理**：登录成功后将User对象存入HttpSession，后续请求通过LoginInterceptor验证
- **WebSocket认证**：握手时检查Session中的currentUser，未登录拒绝连接

#### 2.2.2 数据流设计

**添加好友流程：**
```
用户A搜索用户B → 发送好友申请 → 写入friend_request表(status=0)
                                    ↓
用户B查看申请列表 → 点击同意 → 更新status=1
                                    ↓
系统在friend表插入(A,B)和(B,A)两条记录 → 双方好友列表更新
```

**删除分组流程：**
```
用户删除分组X → 查询该组所有好友 → 将groupId设为null → 删除分组记录
```

#### 2.3.2 WebSocket通信设计

**私聊消息流程：**
```
用户A输入消息 → 前端乐观更新显示 → STOMP发送至/app/chat/private
                                            ↓
ChatController接收 → 保存至private_message表 → 解析sender显示名
                                            ↓
推送至/user/{receiverId}/queue/private → 用户B实时收到
                                            ↓
用户B打开会话 → 调用REST API标记已读 → 清除未读徽章
```

**消息状态机：**
```
已发送(0) → 已送达(1) → 已读(2)
   ↑           ↑           ↑
 发送时    对方收到推送   对方打开会话
```

### 2.5 语音消息模块

#### 2.5.1 技术流程

```
用户按住录音按钮 → navigator.mediaDevices.getUserMedia({audio:true})
                        ↓
创建MediaRecorder(audio/webm;codecs=opus) → 开始录音
                        ↓
用户松开按钮 → mediaRecorder.stop() → 合并音频Blob
                        ↓
FileReader.readAsDataURL(blob) → 转为Base64字符串
                        ↓
STOMP发送(msgType=1, audioData=base64String)
                        ↓
后端保存至数据库 → 推送至接收方
                        ↓
接收方 new Audio(base64Data).play() → 播放语音
```

#### 2.5.2 限制与优化
- **时长限制**：最长10秒，防止数据过大
- **缓冲区配置**：WebSocket传输层和STOMP协议层均设置为1MB，支持语音消息
- **乐观更新**：发送时立即显示消息气泡（带旋转动画），3秒后自动消失

```json
{
  "code": 200,
  "message": "success",
```

## 六、性能优化设计

### 6.1 N+1查询优化
- **好友列表**：批量加载好友用户信息，避免逐个查询
- **未读计数**：使用GROUP BY一次性获取所有好友的未读数
- **群消息**：批量加载发送者信息

### 6.2 异步加载优化
- **视图切换**：使用generation counter防止竞态条件
- **懒加载**：聊天记录按需加载，不一次性加载全部

### 6.3 缓存策略
- **Thymeleaf缓存**：生产环境启用
- **数据库连接池**：HikariCP，最大10个连接

## 七、安全设计

### 7.1 认证与授权
- **Session认证**：登录后将User存入Session
- **拦截器**：LoginInterceptor拦截所有请求，排除公开路径
- **WebSocket认证**：握手时验证Session

### 7.2 数据安全
- **密码加密**：BCrypt单向哈希
- **SQL注入防护**：JPA参数化查询
- **XSS防护**：前端escapeHtml转义

### 7.3 权限控制
- **群主权限**：只有群主可以踢人、解散群、修改公告
- **分组权限**：只有分组所有者可以重命名、删除分组
