第 6 章：部署与上线

6.1 线上环境信息

项目配置
域名pp.evog.top
服务器Ubuntu 24.04、OpenJDK 21
反向代理Nginx + Let's Encrypt SSL
应用端口127.0.0.1:10601（仅 Nginx 可访问）
数据库远程 MySQL 8.0

6.2 部署流程

1. 打包应用

./mvnw clean package -DskipTests

2. 上传到服务器

scp target/pp-chat.jar user@server:/opt/pp-chat/

3. 配置 Nginx

server {
    listen 443 ssl;
    server_name pp.evog.top;
    
    ssl_certificate /etc/letsencrypt/live/pp.evog.top/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/pp.evog.top/privkey.pem;
    
    location / {
        proxy_pass http://127.0.0.1:10601;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    
    location /ws {
        proxy_pass http://127.0.0.1:10601/ws;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

4. 启动应用

nohup java -jar /opt/pp-chat/pp-chat.jar --spring.profiles.active=prod > app.log 2>&1 &

6.3 HTTPS 配置

为什么必须配置 HTTPS？

  • 浏览器安全策略要求：getUserMedia() 只能在 HTTPS 或 localhost 下调用
  • 没有 HTTPS，语音录制功能完全无法使用

使用 Let's Encrypt 申请证书

sudo certbot --nginx -d pp.evog.top
部署时的坑：最初没配置 HTTPS，导致语音功能失效，花了很长时间才定位到问题。

6.4 生产环境配置

使用 application-prod.yml 覆盖开发配置：

  • 端口：10601
  • 数据库：远程 MySQL
  • 上传目录：/opt/pp-chat/uploads/
  • 日志级别：INFO

6.5 更新部署

# 1. 停止旧进程
ps aux | grep pp-chat.jar
kill [PID]

# 2. 备份数据
mysqldump > backup.sql

# 3. 上传新版本
scp target/pp-chat.jar user@server:/opt/pp-chat/

# 4. 启动新版本
nohup java -jar /opt/pp-chat/pp-chat.jar --spring.profiles.active=prod > app.log 2>&1 &

6.6 常见问题

问题 1：端口被占用

netstat -tlnp | grep 10601

问题 2：无法连接数据库

检查防火墙、数据库权限、连接字符串

问题 3：文件上传失败

检查上传目录权限、磁盘空间
