第 4 章：前端 SPA 架构

4.1 为什么用原生 JS？

项目采用原生 JavaScript + 模块化设计，没有使用 Vue/React 框架。

原因：
  • 课程要求掌握原生 JavaScript 能力
  • 项目规模适中，不需要复杂状态管理
  • 避免构建工具和打包流程
  • 直接通过 Thymeleaf 渲染加载

4.2 模块划分

文件职责
chat-core.js全局状态、WebSocket 初始化、视图切换
chat-view.js聊天窗口、消息渲染、语音录制、搜索导出
chat-friends.js好友列表、申请处理、通知中心
chat-groups.js群聊列表、群详情、成员管理
chat-profile.js个人中心、资料修改
chat-ui.jsUI 组件（模态框、抽屉、分隔线）
theme.js主题切换（日间/夜间/跟随系统）
注意：项目中有 chat.js 是早期单文件版本，已废弃。实际运行时加载的是拆分后的 chat-*.js 模块。

4.3 视图切换机制

function switchView(view) {
    currentView = view;
    currentChat = null;
    const gen = ++viewGeneration;
    
    // 清空内容区和抽屉
    const content = document.getElementById('contentArea');
    if (content) content.innerHTML = '';
    const drawer = document.getElementById('infoDrawer');
    if (drawer) drawer.classList.add('hidden');
    
    // 加载对应视图
    switch (view) {
        case 'chat': loadChatView(gen); break;
        case 'friends': loadFriendsView(gen); break;
        case 'groups': loadGroupsView(gen); break;
        case 'notifications': loadNotificationsView(gen); break;
        case 'profile': loadProfileView(gen); break;
    }
}
关键设计：使用 generation counter 防止异步加载时视图混乱。

4.4 主题系统

支持三种主题：日间模式、夜间模式、跟随系统。

  • 主题配置存储在 localStorage
  • 通过 CSS 变量控制颜色
  • 切换时平滑过渡

4.5 前端状态管理

使用全局变量管理核心状态：

  • currentUser：当前登录用户
  • currentView：当前视图
  • currentChat：当前聊天对象
  • stompClient：WebSocket 连接
  • viewGeneration：视图代数（防止异步冲突）
答辩建议：可以主动说明"如果项目继续扩展，会考虑引入 Vue 或 React"，显示你对技术选型的思考。
