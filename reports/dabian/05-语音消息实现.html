第 5 章：语音消息实现

这是答辩重点！

语音消息是项目的特色功能，涉及前端录音、实时传输、文件存储多个环节，是展示技术深度的好机会。

5.1 完整实现链路

前端录音（MediaRecorder）
    ↓
转为 Base64 Data URL
    ↓
通过 WebSocket 发送到后端
    ↓
后端解码 Base64
    ↓
保存为文件（uploads/audio/xxx.webm）
    ↓
数据库只存 URL（/uploads/audio/xxx.webm）
    ↓
前端接收消息，显示语音气泡
    ↓
点击播放，加载音频文件

5.2 前端录音实现

核心代码

// 申请麦克风权限
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });

// 创建录音器
const recorder = new MediaRecorder(stream, {
    mimeType: 'audio/webm;codecs=opus'
});

// 收集音频数据
let chunks = [];
recorder.ondataavailable = e => {
    if (e.data && e.data.size > 0) chunks.push(e.data);
};

// 录音结束
recorder.onstop = () => {
    const blob = new Blob(chunks, { type: 'audio/webm' });
    const reader = new FileReader();
    reader.onloadend = () => {
        const base64 = reader.result;  // data:audio/webm;base64,xxx
        // 通过 WebSocket 发送
        stompClient.send('/app/chat/private', {}, JSON.stringify({
            msgType: 1,
            audioData: base64,
            content: '[语音] 10s'
        }));
    };
    reader.readAsDataURL(blob);
};

// 开始录音
recorder.start();
关键点：
  • 使用 audio/webm;codecs=opus 格式，浏览器支持好，压缩率高
  • 限制录音时长 10 秒，避免文件过大
  • 通过 FileReader 转为 Base64，方便传输

5.3 后端文件保存

public String saveBase64Audio(String base64Data) throws IOException {
    // 1. 分离头部和数据
    String[] parts = base64Data.split(",");
    String data = parts.length > 1 ? parts[1] : parts[0];
    
    // 2. Base64 解码
    byte[] audioBytes = Base64.getDecoder().decode(data);
    
    // 3. 检查文件大小
    if (audioBytes.length > MAX_FILE_SIZE) {
        throw new IOException("音频文件大小超过限制（10MB）");
    }
    
    // 4. 生成文件名
    String filename = UUID.randomUUID() + ".webm";
    
    // 5. 保存到磁盘
    Path dir = Paths.get(uploadDir).resolve("audio");
    if (!Files.exists(dir)) Files.createDirectories(dir);
    Path filepath = dir.resolve(filename);
    Files.write(filepath, audioBytes);
    
    // 6. 返回 URL
    return "/uploads/audio/" + filename;
}

5.4 为什么不直接存数据库？

方案优点缺点
Base64 存 MySQL 实现简单 数据库膨胀严重，查询慢，备份困难
文件存磁盘 + URL 存数据库 数据库轻量，扩展性好，可用 CDN 加速 需要处理文件管理
答辩高频问题

Q: 你们最开始是怎么做的？

回答：最初确实尝试过把 Base64 直接存 MySQL，但很快发现数据库膨胀得很快，后来改为文件落盘方案。这个过程让我们理解了"数据库应该存什么，文件系统应该存什么"。

5.5 HTTPS 与麦克风权限

浏览器的安全策略要求：getUserMedia() 只能在 HTTPS 或 localhost 环境下调用。

部署时的坑：

项目最初部署到服务器时没有配置 HTTPS，导致语音录制功能完全无法使用。后来通过 Nginx + Let's Encrypt 配置了 SSL 证书才解决。

5.6 为什么限制 10 秒？

  • 传输稳定性：时长过长，Base64 编码后体积大，WebSocket 传输容易超时
  • 用户体验：聊天场景下，短语音更符合使用习惯
  • 存储成本：控制单个文件大小，便于管理
