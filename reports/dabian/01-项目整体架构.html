答辩要点

为什么选择 Spring Boot 而不是更轻量的框架？

推荐回答：Spring Boot 是课程要求的技术栈，同时它提供了成熟的生态、自动配置和开箱即用的 WebSocket 支持，适合快速开发完整项目。

表名作用

关键设计决策：
  • 好友关系双向存储：A 加 B 为好友时，同时插入 (A, B) 和 (B, A) 两条记录，简化查询逻辑
  • 群邀请表复用：通过 type 字段区分"邀请入群"(0) 和"申请入群"(1)
  • 语音消息：数据库只存 URL，实际文件保存在 uploads/audio/

1.4 认证与权限设计

为什么不用 Spring Security？

项目采用 Session + 自定义拦截器的方式实现认证，而没有使用 Spring Security 的 Filter Chain。

答辩时可能被问到

Q: 为什么不用 Spring Security？

推荐回答：

  • 项目需求相对简单，只需要登录/登出和权限拦截
  • Session 认证更直观，容易理解和调试
  • 自定义拦截器可以更灵活地控制哪些路径需要认证
  • 避免了 Spring Security 的复杂配置和学习成本

认证流程

// 登录时
session.setAttribute("currentUser", user);

// LoginInterceptor 拦截未登录请求
if (session.getAttribute("currentUser") == null) {
    response.sendRedirect("/login");
    return false;
}

1.5 架构优势与不足

优势

  • 单体架构，部署简单：一个 JAR 包即可运行，适合课程项目
  • 技术栈成熟：Spring Boot 生态完善，问题容易解决
  • 前后端职责清晰：后端只负责数据和业务，前端负责交互
  • 实时通信与 REST API 分离：聊天消息走 WebSocket，其他操作走 HTTP

不足与改进方向

  • 缺少缓存层：高频查询（如好友列表）可引入 Redis 缓存
  • 文件存储在本地：生产环境建议使用对象存储（OSS）
  • 缺少消息队列：群聊消息可通过 MQ 异步分发，提升性能
  • 前端无构建工具：原生 JS 开发效率较低，可引入 Vite 或 Webpack
答辩建议

不要只说优点，主动提出不足和改进方向，显示你对架构有更深层的思考。
