第 2 章：核心功能实现

2.1 账户模块

注册流程

public String register(String username, String password, String nickname) {
    // 1. 检查用户名是否已存在
    if (userRepository.findByUsername(username).isPresent()) {
        return "用户名已存在";
    }
    
    // 2. 密码加密
    String encodedPassword = passwordEncoder.encode(password);
    
    // 3. 创建用户对象
    User user = new User();
    user.setUsername(username);
    user.setPassword(encodedPassword);
    user.setNickname(nickname);
    user.setCreatedAt(LocalDateTime.now());
    
    // 4. 保存到数据库
    userRepository.save(user);
    return null;
}
关键点：密码使用 BCrypt 加密，不存明文。每次加密结果都不同（带盐值），即使相同密码也无法通过数据库比对破解。

登录流程

public User login(String username, String password) {
    Optional opt = userRepository.findByUsername(username);
    if (opt.isEmpty()) {
        return null;
    }
    
    User user = opt.get();
    // BCrypt 自动处理盐值验证
    if (passwordEncoder.matches(password, user.getPassword())) {
        user.setLastLogin(LocalDateTime.now());
        user.setLoginCount(user.getLoginCount() + 1);
        userRepository.save(user);
        return user;
    }
    return null;
}
答辩可能被问

Q: 如果用户忘记密码怎么办？

回答：项目实现了"忘记密码"功能，用户输入用户名和新密码即可重置。生产环境应该加入验证码或邮件验证。

2.2 好友模块

好友关系为什么双向存储？

当 A 添加 B 为好友时，数据库中插入两条记录：

  • (user_id=A, friend_id=B)
  • (user_id=B, friend_id=A)
优势：
  • 查询 A 的好友列表：WHERE user_id = A，无需 UNION
  • 删除好友关系：同时删除两条记录，保持一致性
  • 查询效率高，不需要复杂的 JOIN 或 OR 条件

好友申请流程

步骤操作
1A 搜索用户，找到 B
2A 发送好友申请，写入 pp_friend_request 表
3B 在通知中心看到待处理申请
4B 同意 → 写入两条 pp_friend 记录
5B 拒绝 → 更新申请状态为"已拒绝"

好友分组

// 移动好友到新分组
public void moveFriend(Long userId, Long friendId, Long newGroupId) {
    Friend friend = friendRepository
        .findByUserIdAndFriendId(userId, friendId)
        .orElseThrow();
    
    friend.setGroupId(newGroupId);
    friendRepository.save(friend);
}
注意

项目早期出现过 bug：好友的 group_id 可能指向其他用户的分组。已通过数据修复脚本解决。

2.3 群聊模块

群聊角色设计

角色role 值权限
群主2修改公告、踢人、解散群
管理员1踢人（预留，当前未实现）
普通成员0聊天、查看群详情、退群

邀请入群 vs 申请入群

两种流程共用 pp_group_invitation 表，通过 type 字段区分：

type流程from_user_idto_user_id
0邀请入群群主被邀请者
1申请入群申请者群主
设计思路：复用一张表，减少表数量，统一在通知中心处理。

2.4 消息模块

私聊消息

  • 发送方式：WebSocket STOMP，发送到 /app/chat/private
  • 接收方式：订阅 /user/queue/private
  • 存储：保存到 pp_private_message 表
  • 已读标记：通过 status 字段管理

群聊消息

  • 发送方式：发送到 /app/chat/group
  • 接收方式：所有成员订阅 /topic/group/{groupId}
  • 存储：保存到 pp_group_message 表
  • 广播机制：一条消息发送后，所有在线成员实时收到
答辩技巧

主动对比私聊和群聊的实现差异，展示你对 STOMP 订阅机制的理解。

2.5 后台管理

为什么要独立的管理员表？

  • 管理员和普通用户权限完全不同
  • 独立登录入口，避免混淆
  • Session 管理分离，不会互相影响

后台主要功能

  • 仪表盘：用户数、好友数、群聊数、消息数统计
  • 数据管理：查看、搜索、删除用户/好友/群聊/消息
  • 密码重置：管理员可重置用户密码
  • 异常数据清理：删除孤立的好友关系、空群等
注意

删除用户时需要级联处理：好友关系、群成员、消息、会话等都要一并清理。
