第 3 章：WebSocket 实时通信

3.1 为什么用 WebSocket？

相比 HTTP 轮询，WebSocket 提供了真正的双向通信能力，服务器可以主动推送消息给客户端。

技术优点缺点
HTTP 轮询实现简单浪费带宽，延迟高，服务器压力大
WebSocket双向通信，实时性强，服务器可主动推送需要浏览器支持

3.2 STOMP 协议

STOMP（Simple Text Oriented Messaging Protocol） 是运行在 WebSocket 之上的消息协议。

为什么不直接用 WebSocket？

原生 WebSocket 只提供传输通道，没有消息路由、订阅等概念。STOMP 增加了：

  • 消息目的地（destination）
  • 订阅机制（subscribe）
  • 消息代理（broker）

本项目的配置

  • WebSocket 端点：/ws
  • 应用前缀：/app
  • 广播前缀：/topic（群聊）
  • 点对点前缀：/queue（私聊）

3.3 私聊消息链路

发送流程

// 前端发送
stompClient.send("/app/chat/private", {}, JSON.stringify({
    senderId: currentUserId,
    receiverId: friendId,
    content: "你好",
    msgType: 0
}));

// 后端处理
@MessageMapping("/chat/private")
public void sendPrivateMessage(@Payload ChatMessage message, Principal principal) {
    // 1. 校验发送者身份
    // 2. 保存消息到数据库
    // 3. 推送给接收者
    messagingTemplate.convertAndSendToUser(
        message.getReceiverId().toString(),
        "/queue/private",
        message
    );
}

接收流程

// 前端订阅
stompClient.subscribe('/user/queue/private', (message) => {
    const data = JSON.parse(message.body);
    appendMessage(data);
});
关键：后端只推送给接收者，发送者由前端立即渲染，避免重复。

3.4 群聊消息链路

发送流程

// 前端发送
stompClient.send("/app/chat/group", {}, JSON.stringify({
    senderId: currentUserId,
    receiver: groupId,
    content: "大家好"
}));

接收流程

// 前端订阅
stompClient.subscribe('/topic/group/' + groupId, (message) => {
    const data = JSON.parse(message.body);
    appendMessage(data);
});
私聊 vs 群聊：
  • 私聊：点对点，/user/{userId}/queue/private
  • 群聊：广播，/topic/group/{groupId}

3.5 握手认证

WebSocket 连接建立时，需要从 HTTP Session 读取用户信息，设置为 STOMP Principal，这样私聊消息才能准确路由。

常见问题：如果忘记设置 Principal，convertAndSendToUser 会失败，私聊消息无法推送。

3.6 Buffer 限制问题

默认消息大小限制 64KB，语音消息 Base64 编码后会超出。

解决：在 application.yml 和 WebSocketConfig 中增大到 1MB。
