第 7 章：常见问题与答题思路

答辩核心原则

  • 不要只说"做了什么"，要说"为什么这样做"
  • 主动展示技术亮点，不要等老师问
  • 承认不足并说明改进方向
  • 用具体例子，不要空谈概念

高频问题速查

Q1: 项目最大的技术难点？

推荐回答（语音模块）：
  • 难点1：浏览器麦克风权限需要 HTTPS，最初部署时没配置导致功能失效
  • 难点2：语音 Base64 编码后超过 WebSocket 默认 buffer 限制（64KB）
  • 难点3：最初把音频存数据库导致严重膨胀
  • 解决：配置 HTTPS、增大 buffer 到 1MB、限制时长 10 秒、改用文件系统存储

Q2: 为什么不用 Spring Security？

推荐回答：

采用 Session + 自定义拦截器实现认证，原因：

  • 项目需求相对简单，只需登录/登出和权限拦截
  • 自定义拦截器更直观，容易理解和调试
  • 避免 Spring Security 的复杂配置

Q3: 好友关系为什么双向存储？

推荐回答：

A 加 B 为好友时，同时插入 (A, B) 和 (B, A) 两条记录

优点：查询效率高，WHERE user_id = A 无需 UNION；删除同时删两条，保持一致性

缺点：占用存储空间多，但对好友数量不大的场景可接受

Q4: 私聊和群聊有什么不同？

私聊群聊
发送/app/chat/private/app/chat/group
接收/user/queue/private/topic/group/{id}
方式点对点（一对一）广播（一对多）

Q5: WebSocket 和 HTTP 轮询有什么区别？

HTTP 轮询：客户端反复请求，有延迟，服务器压力大

WebSocket：一次连接持续通信，实时，服务器主动推送

Q6: 如果用户量很大怎么优化？

  • 引入 Redis 缓存好友列表、用户信息
  • 群聊消息通过 MQ 异步分发
  • 数据库读写分离、消息表按时间分片
  • 使用对象存储（OSS）替代本地文件
  • WebSocket 多实例 + 消息路由层

Q7: 项目有哪些不足？

主动说不足显示深度：
  • 安全性：密码重置应该加验证码
  • 性能：缺少缓存层
  • 可扩展性：单体架构难以水平扩展
  • 前端：原生 JS 开发效率低
  • 测试：缺少压力测试

Q8: 你从这个项目学到了什么？

技术层面：深入理解 WebSocket 实时通信、文件处理、数据库设计

工程层面：经历了从本地开发到线上部署的完整流程，学会排查线上问题

答辩技巧

黄金法则：
  1. 开场主动介绍：项目背景 → 技术栈 → 核心功能 → 技术亮点
  2. 讲故事：说"遇到什么问题、怎么解决的"
  3. 展示代码：准备 1-2 段核心代码片段主动讲解
  4. 现场演示：最好演示一个完整流程
  5. 承认不足：主动说不足和改进方向

最后检查清单

  • ☐ 线上地址能访问（https://pp.evog.top）
  • ☐ 测试账号准备好（至少两个）
  • ☐ 后台账号记住（admin/admin123）
  • ☐ 能说出 1-2 个技术难点和解决方案
  • ☐ 能画出 WebSocket 消息流程图
  • ☐ 能说出项目不足和改进方向
