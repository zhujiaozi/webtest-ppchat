# PP 在线聊天系统 — 数据库设计文档

## 一、数据库概述

### 1.1 数据库信息
- **数据库名称**：gove_sqlpub（生产环境）/ pp_db（开发环境）
- **数据库类型**：MySQL 8.0
- **字符集**：utf8mb4
- **ORM框架**：Spring Data JPA + Hibernate
- **建表策略**：JPA `ddl-auto: update`（开发环境自动建表）

## 二、表结构详细设计

### 2.1 pp_user — 用户表

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | BIGINT | PK, AUTO_INCREMENT | - | 主键 |
| username | VARCHAR(50) | UNIQUE, NOT NULL | - | 登录用户名 |
| password | VARCHAR(255) | NOT NULL | - | BCrypt加密密码 |
| nickname | VARCHAR(50) | - | NULL | 显示昵称 |
| avatar | VARCHAR(500) | - | NULL | 头像URL路径 |
| security_question | VARCHAR(200) | - | NULL | 安全问题（预留） |
| security_answer | VARCHAR(200) | - | NULL | 安全问题答案（预留） |
| status | INT | - | 0 | 在线状态：0=离线, 1=在线 |
| last_login | DATETIME | - | NULL | 最近登录时间 |
| login_count | INT | - | 0 | 累计登录次数 |
| created_at | DATETIME | - | CURRENT_TIMESTAMP | 注册时间 |
| updated_at | DATETIME | - | CURRENT_TIMESTAMP | 更新时间 |

**索引：**
- PRIMARY KEY (`id`)
- UNIQUE INDEX `uk_username` (`username`)

**JPA实体：** `com.ncu.pp.entity.User`

---

### 2.2 pp_friend_group — 好友分组表

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | BIGINT | PK, AUTO_INCREMENT | - | 主键 |
| user_id | BIGINT | FK → pp_user.id, NOT NULL | - | 所属用户 |
| name | VARCHAR(50) | NOT NULL | - | 分组名称 |
| sort_order | INT | - | 0 | 排序权重 |

**索引：**
- PRIMARY KEY (`id`)
- INDEX `idx_user_id` (`user_id`)

**JPA实体：** `com.ncu.pp.entity.FriendGroup`

---

### 2.3 pp_friend — 好友关系表

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | BIGINT | PK, AUTO_INCREMENT | - | 主键 |
| user_id | BIGINT | FK → pp_user.id, NOT NULL | - | 用户A |
| friend_id | BIGINT | FK → pp_user.id, NOT NULL | - | 用户B（好友） |
| group_id | BIGINT | FK → pp_friend_group.id | NULL | 所属分组 |
| remark | VARCHAR(50) | - | NULL | 好友备注名 |
| created_at | DATETIME | - | CURRENT_TIMESTAMP | 成为好友时间 |

**索引：**
- PRIMARY KEY (`id`)
- UNIQUE INDEX `uk_user_friend` (`user_id`, `friend_id`) — 防止重复好友关系
- INDEX `idx_user_id` (`user_id`)
- INDEX `idx_group_id` (`group_id`)

**设计说明：**
- 双向存储：A加B为好友时插入 `(A, B)` 和 `(B, A)` 两条记录
- 查询时只需 `WHERE user_id = ?`，无需UNION

**JPA实体：** `com.ncu.pp.entity.Friend`

---

## 三、关键查询语句

### 3.1 好友相关查询

```sql
-- 获取用户的所有好友（含备注名）
SELECT f.*, u.nickname AS friend_name
FROM pp_friend f
JOIN pp_user u ON f.friend_id = u.id
WHERE f.user_id = ?;

-- 搜索用户（用于加好友）
SELECT * FROM pp_user
WHERE id <> ?
  AND (username LIKE '%keyword%' OR nickname LIKE '%keyword%');

-- 搜索好友（用于发起私聊）
SELECT u.* FROM pp_user u
WHERE u.id <> ?
  AND (u.username LIKE '%keyword%' OR u.nickname LIKE '%keyword%')
  AND u.id IN (SELECT friend_id FROM pp_friend WHERE user_id = ?);
```

### 3.2 消息相关查询

```sql
-- 获取两人完整对话
SELECT * FROM pp_private_message
WHERE (sender_id = ? AND receiver_id = ?)
   OR (sender_id = ? AND receiver_id = ?)
ORDER BY created_at ASC;

-- 批量获取未读消息数
SELECT sender_id, COUNT(*) AS unread_count
FROM pp_private_message
WHERE receiver_id = ? AND status < 2
GROUP BY sender_id;

-- 标记消息为已读
UPDATE pp_private_message
SET status = 2
WHERE sender_id = ? AND receiver_id = ? AND status < 2;
```

### 3.3 群聊相关查询

```sql
-- 获取用户加入的所有群
SELECT gc.* FROM pp_group_chat gc
JOIN pp_group_member gm ON gc.id = gm.group_id
WHERE gm.user_id = ?;

-- 获取群成员列表
SELECT gm.*, u.nickname
FROM pp_group_member gm
JOIN pp_user u ON gm.user_id = u.id
WHERE gm.group_id = ?;
```

## 四、数据字典

### 4.1 状态码定义

**用户状态 (user.status):**
| 值 | 含义 |
|----|------|
| 0 | 离线 |
| 1 | 在线 |

**好友申请状态 (friend_request.status):**
| 值 | 含义 |
|----|------|
| 0 | 待处理 |
| 1 | 已同意 |
| 2 | 已拒绝 |

**消息状态 (private_message.status):**
| 值 | 含义 |
|----|------|
| 0 | 已发送 |
| 1 | 已送达 |
| 2 | 已读 |

**消息类型 (msg_type):**
| 值 | 含义 |
|----|------|
| 0 | 文本消息 |
| 1 | 语音消息 |

**群成员角色 (group_member.role):**
| 值 | 含义 |
|----|------|
| 0 | 普通成员 |
| 1 | 管理员 |
| 2 | 群主 |

## 五、数据库维护

### 5.1 清理脚本

项目提供 `docs/clean_database.sql` 用于清空所有业务数据：

```sql
USE gove_sqlpub;
SET FOREIGN_KEY_CHECKS = 0;
TRUNCATE TABLE pp_private_message;
TRUNCATE TABLE pp_group_message;
TRUNCATE TABLE pp_group_member;
TRUNCATE TABLE pp_group_chat;
TRUNCATE TABLE pp_friend_request;
TRUNCATE TABLE pp_friend;
TRUNCATE TABLE pp_friend_group;
SET FOREIGN_KEY_CHECKS = 1;
```

### 5.2 备份建议

- 定期备份 MySQL 数据库
- 备份上传文件目录（头像、语音文件）
- 使用 mysqldump 工具进行全量备份
